# 2026-08-03 BG 좌석 배정·월드 파티션·레벨 분리

BG(뱅! 카드게임 프로토타입)에서 좌석 배정 컴포넌트를 만들고 메인메뉴 레벨을 분리했다. 발행본: [/posts/til-baam-seat-assignment-level-split/](/posts/til-baam-seat-assignment-level-split/) — **구현 결정(1~3·5항)만 발행**했고, 진단 과정과 월드 파티션·툴링 트러블슈팅(4·6·7항)은 성격이 달라 발행에서 제외했다.

## 오늘 한 일 요약

1. **좌석 배정 훅 위치** — `PostLogin`에서 `Super` 앞에 좌석을 주면 늦다. 엔진이 `Login()` → `InitNewPlayer()` 안에서 시작 지점을 골라 컨트롤러의 `StartSpot`에 캐시하기 때문. 배정을 `InitNewPlayer` 오버라이드로 옮겨 해결. 이 시점에 `PlayerState`는 존재하지만 이름이 비어 있어 컨트롤러 이름으로 대체.
2. **좌석 번호는 연속일 필요 없음** — 턴 진행이 `GetAliveSeatsInTableOrder()`로 실제 좌석 번호를 정렬해 순환하므로 구멍이 있어도 동작한다. 4명이 `{0,1,2,3}` 대신 `{0,2,4,6}`으로 흩어 앉도록 `BuildSeatOrder`를 짝수→홀수(`0,2,4,6,1,3,5`)로 변경. 입장은 결정적(빈 자리 중 앞자리), 판 시작은 랜덤(자리 집합 고정 + 사람만 Fisher-Yates).
3. **첫 턴은 보안관** — 좌석·역할을 독립 셔플하므로 `Alive[0]`(최소 좌석)로는 보안관을 못 찾는다. 역할 태그로 조회하도록 변경. 호출 순서가 `RandomizeSeats` → `AssignRoles` → `StartMatch`라 조회 시점에 태그가 확정돼 있다. `main` 브랜치를 따로 빌드해 4프로세스로 확인했더니 기존에도 첫 턴이 좌석 0이었다 — 이번 변경으로 생긴 문제가 아님.
4. **월드 파티션(OFPA)** — `TestMap`이 World Partition 맵이라 액터가 `.umap`에 안 들어가고 `__ExternalActors__/.../SLX36TML44YCJ3EHPEF28T.uasset`처럼 액터당 파일 하나로 떨어진다(폴더명은 GUID 해시). `PlayerStart` 7개를 놓자 git에 폴더 7개가 신규로 잡혔다. ①같은 액터를 둘이 고치면 바이너리 충돌이라 머지 불가 ②트랜스폼만 바꾸면 `save_current_level()`이 `True`를 반환해도 리로드하면 원위치 — 외부 액터 패키지가 더티로 안 잡히는 듯. 액터를 지우고 새로 스폰하니 정상 기록 ③`.umap` 본체도 함께 `M`으로 뜬다(액터 목록·파티션 정보).
5. **레벨 분리** — 프로젝트 결정이 "맵 이동 없음"(PlayerState 재생성·심리스 트래블·ASC 재초기화 회피). 메인메뉴는 세션 생성 전이라 이 문제군 밖이므로 예외로 두고 `L_MainMenu` 분리. 호스트가 메뉴 레벨에서 리슨을 열면 안 되므로 "게임 맵이면 제자리(`StartListenInPlace`), 아니면 1회 `ServerTravel ?listen`"로 분기. 클라이언트는 `JoinSession`이 호스트 IP로 `ClientTravel` 하므로 수정 불필요.
6. **UMG·툴링 잔가시** — ①위젯 BP의 `parent_class`가 조용히 무시된다(생성 후 CDO 타입 확인 → `BlueprintEditorLibrary.reparent_blueprint`로 교정) ②`HighResShot`은 UMG를 담지 않아 메뉴 캡처가 하늘·땅만 나온다(Win32 `GetWindowRect` + `Graphics.CopyFromScreen`으로 창 직접 캡처) ③Windows PowerShell 5.1은 BOM 없는 UTF-8 `.ps1`을 ANSI로 읽어 한글 주석 스크립트가 통째로 파싱 실패(스크립트는 ASCII로) ④게임 창에 콘솔 명령을 보낼 때 `SetForegroundWindow`만으로는 포커스가 안 잡혀, 창 중앙 클릭 후 키 전송 + 실패 시 재시도 루프 필요.
7. **실패 기록 — 월드 파티션 맵 이름 변경 2회 실패.** `TestMap` → `L_PvPLobby` 시도.
   - **1차(에디터 안 `rename_assets`)**: 외부 액터 159개 중 16개만 옮겨진 상태로 멈췄고, 그 사이 레벨을 열자 `Fatal error: World Memory Leaks`로 에디터 사망. 원인은 호출 타임아웃 — 클라이언트는 30초에 끊겼지만 언리얼은 계속 작업 중이었다.
   - **2차(헤드리스 `-run=pythonscript`)**: 커맨드릿에서 `load_asset`이 월드를 열지 못해 rename이 무동작이었는데, 뒤이은 "리다이렉터 정리" 코드가 실제 맵을 삭제. `does_asset_exist`는 리다이렉터든 실제 에셋이든 `True`이고, rename이 실패했으니 그 경로엔 진짜 맵이 있었다. `git checkout -- BG/Content`로 복구.

   ```python
   # 이 코드가 원본을 지웠다 — 리다이렉터인지 확인하지 않았다
   if unreal.EditorAssetLibrary.does_asset_exist(SRC_PKG):
       unreal.EditorAssetLibrary.delete_asset(SRC_PKG)
   ```

## 오늘 배운 것 정리

1. **엔진 훅은 "무엇을 하는 함수인가"가 아니라 "내 값이 언제 확정되는가"로 고른다.** `PostLogin`이 폰을 스폰하니 그 앞이면 되겠다는 추측이 틀렸다 — 시작 지점은 그보다 앞에서 이미 캐시된다. 순서가 의심되면 로그로 찍어 확인한다.
2. **내가 단 주석이 곧 근거는 아니다.** "좌석은 빈틈 없이 채워져야 한다"는 전제를 주석에 적어 뒀지만 실제 코드는 그걸 요구하지 않았다. 전제를 적었으면 코드에 그 전제가 있는지 확인한다.
3. **삭제 전에 대상의 정체를 확인한다.** "존재한다"는 "리다이렉터다"가 아니다.
4. **타임아웃은 작업 취소가 아니다.** 호출이 끊겨도 엔진은 계속 돈다. 그 사이 손대면 터진다.
5. **월드 파티션 맵 이름 변경은 에디터 UI로 한다.** 외부 액터 159개를 한 트랜잭션으로 옮겨 주는 보장은 UI에만 있고, 스크립트로는 그 보장을 못 받는다.
