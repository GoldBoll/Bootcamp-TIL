# 2026-07-24 세션 계층 세 겹 — 스팀 초대·방찾기·로비 슬롯 재사용

팀 프로젝트(협동 이사 게임, 저장소 TeamCarry→Coupeng 이관)의 세션 계층은 방코드 하나로 돌아갔다. 이날은 그 위에 친구를 부르는 경로를 늘렸다 — ①스팀 오버레이 초대→수락 자동 참가, ②코드 없이 열린 방을 찾는 세션 브라우저, ③사람이 드나들어도 흐트러지지 않게 하는 로비 슬롯 재사용 수정. 초대·방찾기는 브랜치를 쌓아 만든 뒤 PR로 develop에 머지, 로비 슬롯은 그 뒤 발견해 직접 손봤다. 발행본: [/posts/til-session-invite-browser-lobby-slot/](/posts/til-session-invite-browser-lobby-slot/).

## 오늘 한 일 요약

1. **스팀 초대·수락 자동참가** — 방코드용 플래그(bAllowInvites/bUsesPresence/bUseLobbiesIfAvailable)가 presence 세션 조건을 이미 충족해 오버레이 초대가 그대로 열림. SendSessionInviteToFriend BP 래퍼 + Steam_Invite Exec. 수락 델리게이트(OnSessionUserInviteAccepted)에서 세션 키 검증→기존 세션 Destroy→기존 Travel 재사용 조인.
2. **게임 미실행 수락도 같은 델리게이트로** — Steam OSS PendingInvite가 바인딩 후 Tick에서 발화. 커맨드라인 파싱 불필요(중요 발견).
3. **방찾기 세션 브라우저 구조** — FTCSessionSearchResult / FTCSessionSearchFilter. Steam 쿼리는 문자열 부분검색 불가 → 원시 50개 수신 후 **클라 측 필터**. HostCreateRoom(RoomName) 방 이름 광고(TCRoomName), 방코드 흐름 무변경. RefreshSessionList→OnSessionListReady→JoinSessionByIndex, bWantsListAfterSearch로 기존 경로와 분기.
4. **임시 WBP** — WBP_SessionRow(ResultIndex 보관) + WBP_SessionBrowser, 위젯 간 참조 없이 둘 다 TCSessionFlow 서브시스템 직결. 개인 폴더(/Game/Developers/goldb/UI/)에 소프트 참조(나중 공용 이동). 
5. **검증** — Listen Server PIE는 클라 자동 접속이라 방찾기 경로를 안 밟음 → Play Standalone×2가 정석. E2E: 창A 방 만들기 → 창B 목록 발견(1/4·101ms) → [참가] → 호스트 로비 2명. 디버그 키 F9는 TC.GrabDebugToggle과 충돌 → 전수 스캔 후 F10. 토글 바인딩은 기저 AGameUIPlayerController에(타이틀 PC가 ATCPlayerController 파생 아님).
6. **로비 슬롯 재사용 수정(직접)** — NextSlotIndex 단조 증가 방식이 퇴장 슬롯 회수 안 함 → 재진입 반복 시 슬롯이 보드 범위(0~3) 초과 → 보드엔 안 보이는데 AreAllPlayersReady 카운트엔 포함(유령 인원). 수정: FindFreeSlotIndex()가 PlayerArray 스캔으로 빈 칸(bUsed[4]) 중 최저 반환, PostLogin·Seamless 두 경로 교체. **퇴장 회수 코드 불필요** — PlayerState가 빠지면 스캔이 자동 인식. MaxLobbySlots=4 상수화. 3회 재진입 재검증에서 항상 슬롯 1 재사용·보드 정상.

## 오늘 배운 것 정리

1. **초대는 만들기 전에 있는지 본다** — presence 세션 설정이 초대 전제와 같아, 방코드용 플래그가 오버레이 초대를 그대로 열어줬다. 미실행 수락도 PendingInvite로 같은 델리게이트에 들어와 커맨드라인 파싱이 필요 없다.
2. **서버가 못 하는 걸 클라로** — Steam 검색은 부분검색 불가. 원시 결과를 받아 클라에서 거르는 편이, 규모가 작으면 서버 쿼리보다 단순하다.
3. **테스트 환경이 검증할 경로를 실제로 타는지부터** — Listen Server PIE는 자동 접속이라 방찾기를 못 밟는다. Standalone×2라야 목록→참가 경로를 검증한다.
4. **회수 코드는 빠뜨리기 쉬우니 아예 안 만든다** — 슬롯을 발급·회수로 관리하면 나가는 경로마다 반납을 심어야 하고 하나만 빠져도 유령 인원이 샌다. 배정 때마다 PlayerArray를 스캔해 빈 칸을 찾으면 반납 코드 없이 맞는다. 상태를 들고 있지 말고 실제 상태를 다시 읽는 게 누수에 강하다.
