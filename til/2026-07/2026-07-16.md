## 1. 클라이언트 1인 운반 "벽" — 리쉬 부착점의 기준 어긋남

**증상**: 1인 가구를 들고 전진하면 **클라이언트에서만** 어느 순간 입력이 깎여 제자리걸음이 되거나, 전진 입력이 사선 이동으로 휘어버린다. 호스트는 정상. 어제 리쉬로 밴딩을 없앤 직후라 "리쉬가 너무 조이나?" 싶었지만, 반경 튜닝으로는 잡히지 않았다.

**구조 분석 — 서버와 클라가 서로 다른 자로 재고 있었다**: 리쉬 입력 필터는 "부착점(Att)에서 반경 R 밖으로 나가는 원심 입력 성분"을 깎는다. 문제는 이 부착점을 계산하는 기준.

- 서버: 가구의 **실제 트랜스폼**에서 부착점을 계산
- 클라: **보간된 액터 위치**에서 계산 — 이동 중엔 보간이 서버보다 뒤처지므로 부착점이 항상 **뒤로 밀려** 있다

클라 기준 부착점이 뒤에 있으니, 순수 전진 입력도 "부착점에서 멀어지는 원심 성분"으로 오판되어 깎인다. 깎이는 방향이 비대칭이라 전진이 사선으로 휘고, 심하면 벽처럼 막힌다. 여기에 서버가 매 틱 다듬는 앵커 오프셋(테더·정면 복원)이 이벤트 멀티캐스트(그랩·리셋 시점)에만 실려 내려와, 시간이 지날수록 클라 부착점이 수십 uu까지 어긋나 있었다.

**해결 — 측정 기준 통일 + 소프트 숄더**:

① 클라 부착점을 보간 위치 대신 **복제된 서버 트랜스폼** 기준으로 계산:

```cpp
// 클라는 보간된 액터 위치가 서버보다 뒤처져(이동 중) 부착점이 뒤로 밀리고, 그 어긋난
// 기준으로 전진 입력이 깎여 사선 이동이 된다 — 복제된 서버 트랜스폼 기준으로 계산
const bool    bAuth   = Owner->HasAuthority();
const FVector FurnLoc = bAuth ? Owner->GetActorLocation() : ServerLocation;
const float   FurnYaw = bAuth ? Owner->GetActorRotation().Yaw : ServerRotation.Yaw;
OutAttach = GetAttachedLocation(Player, FurnLoc - FVector(0.0f, 0.0f, CurrentHeightOffset), FurnYaw);
```

② 서버가 매 틱 다듬는 앵커 오프셋을 **0.5초마다 클라로 재동기화** (Reliable RPC 과다 방지 스로틀):

```cpp
// 테더·정면 복원이 매 틱 다듬는 오프셋은 이벤트 멀티캐스트(그랩·리셋)에 안 실려
// 클라 리쉬 부착점이 수십 uu 어긋난다 — 0.5초마다 재동기화
if (GFrameCounter % 30 == 0)
{
    Multicast_SetPlayerAnchor(Players[0], Anc->InitialFurnitureYaw,
        Anc->InitialPlayerYaw, Anc->InitialAimYaw, Anc->InitialOffset);
}
```

③ 리쉬 반경을 **서버·클라 동일 53**으로 통일. 어제는 "클라 여유는 좁게(-8)"가 결론이었는데 오늘 뒤집었다 — 그 -8은 **측정 기준이 어긋난 상태**에서 클라가 서버 한계 밖까지 걸어가는 걸 막던 보정이었다. 기준을 통일해 서버·클라 측정이 일치하니 보정의 전제가 사라졌고, 오히려 좁은 반경이 정상 전진을 깎는 부작용만 남는다. 반경은 운반 보행의 평형 간극(가구 추격 지연 + 가구 측 대칭 클램프 48) 40~50 위로 잡아야 한다.

④ 입력 필터를 하드 컷에서 **10uu 소프트 숄더**로 — 경계에 상주하는 보행 평형 상태에서 입력이 벽처럼 뚝 끊기는 것 방지. 관성 클램프와 서버 안전망은 숄더 밖(R+10)에서만 개입해 필터가 허용한 부분 전진을 되막지 않는다:

```cpp
// 소프트 숄더: 반경 초과 10uu에 걸쳐 점진 차단 — 하드 컷은 경계에 상주하는 보행
// 평형 상태에서 입력을 벽처럼 끊는다 (초과분이 클수록 강하게 차단)
const float Soft = FMath::Clamp((Dist - R) / 10.0f, 0.0f, 1.0f);
const FVector Result = (Outward > 0.0f) ? WorldInput - Away * (Outward * Soft) : WorldInput;
```

⑤ 입력이 깎일 때만 발화하는 진단 로그(F9 게이트) 추가 — 입력 각도 → 결과 각도(%), 깎임량, 부착 거리/허용 반경, 충돌 무시 상태를 한 줄에. 재발하면 즉시 어느 항이 어긋났는지 판별할 수 있다.

## 2. 몸통 축 카메라 직결과 두 개의 동결 버그

**배경**: 인원 충족 1인 운반의 몸통 목표를 매 틱 카메라 정면(`GetBaseAimRotation().Yaw`) 기준으로 계산하게 바꿨다. 기존 앵커 상대각 방식은 회전막힘 리셋이 쌓일 때마다 카메라와 몸의 관계가 영구히 틀어졌다. 끌기(인원 미달)와 2인+ 들것은 기존 방식(회전 동결·앵커 기준) 유지.

**버그 ① — 리셋 재기록이 몸을 휙 돌린다**: 회전막힘 리셋은 가구 기준각(`InitialFurnitureYaw`)을 현재 각으로 재기록하는데, 몸통 기준(`InitialPlayerYaw`)을 그대로 두면 몸통 목표가 그랩 시점 값으로 되돌아가 몸이 휙 돌아간다. 가구 기준이 이동한 만큼 몸통 기준도 **델타 시프트로 연속 보존**:

```cpp
// 몸통 기준은 델타 시프트로 연속 보존 — 가구기준만 현재로 재기록하면
// 몸통 목표가 그랩 시점 값으로 되돌아가 몸이 휙 돌아간다
Anc.InitialPlayerYaw    = FRotator::NormalizeAxis(Anc.InitialPlayerYaw
    + FMath::FindDeltaAngleDegrees(Anc.InitialFurnitureYaw, ActualYaw));
Anc.InitialFurnitureYaw = ActualYaw;
Anc.InitialAimYaw       = P->GetBaseAimRotation().Yaw;   // 남은 회전 의도 소거 (벽에서 갈림 반복 방지)
```

**버그 ② — 무입력 1인의 제자리 회전 동결**: 리쉬 모드는 이동 입력이 없는 운반자를 피동(dragged)으로 분류해 회전 의도 가중치에서 제외한다. 2인+에선 맞는 설계지만, 1인 운반자는 **유일한 회전 의도원**이라 피동으로 지우면 제자리(무입력) 카메라 회전이 가중치 0으로 통째로 무시돼 가구·몸이 동결된다. 피동 추적을 2인+에만 적용:

```cpp
// 피동 추적은 2인+만 — 1인 운반자는 유일한 회전 의도원이라 피동으로 지우면
// 제자리(무입력) 카메라 회전이 가중치 0으로 통째로 무시돼 가구·몸이 동결된다
if (Players.Num() >= 2)
{
    CurrentTickDragged.Add(P);
}
```

**가구 바라봄 보정 정리**: 가구가 정면에서 벗어난 초과분만 몸을 가구 쪽으로 굽히는 코스메틱 보정을 유격 10°(기존 30°), 상한 45°로 조이고, 가구가 거의 뒤(120°+)에 있으면 굽힘을 0으로 페이드 — 몸을 획 꺾지 않고 정면 복원이 자연스럽게 데려오게 둔다. 몸통 Yaw는 운반 물리에 안 쓰이는 무상태 계산이라 서버·소유 클라 결과가 저절로 일치한다.

## 3. 급회전 관통 — 성분 보간은 0점을 지난다

**증상**: 1인 운반 중 카메라를 급회전하면 가구가 반대편으로 넘어가면서 **캐릭터 몸을 뚫고** 지나간다. 몸도 홱 돈다.

**구조 분석 — 두 개의 지름길**: 원인은 둘 다 "목표가 즉시 반대편으로 점프"하는 데 있었다.

1. **회전 의도 전량 반영**: 카메라 회전 의도를 가구 목표에 전량 반영하면 급회전 시 제안 위치가 한 틱에 반대편으로 점프한다.
2. **오프셋 X/Y 성분 보간**: 저장 오프셋을 성분별 Lerp로 목표에 접근시키면, 목표 방향이 크게 돌 때 보간 경로가 **0점(몸 중심)을 통과**한다 — 반대편으로 가는 최단 직선이 몸을 가로지르기 때문. 가구가 플레이어를 관통하는 직접 원인.

**해결 — 호를 그리게 한다**:

① 회전 의도에 **±45° 선행 제한** — 실제 가구 회전 진행보다 45°까지만 앞서게 (들것 PairLine의 선행 제한과 동일 원리):

```cpp
// [선행 제한] 1인 카메라 회전 의도는 실제 가구 회전 진행보다 ±45°까지만 앞서게 —
// 전량 반영하면 급회전 시 제안 위치가 반대편으로 점프해 가구가 몸을 가로질러 관통한다
const float ActualDelta = FMath::FindDeltaAngleDegrees(Anc.InitialFurnitureYaw, CurFurnYaw);
const float Lead        = FMath::FindDeltaAngleDegrees(ActualDelta, PlayerYawDelta);
PlayerYawDelta = ActualDelta + FMath::Clamp(Lead, -45.0f, 45.0f);
```

② 오프셋 접근을 **극좌표로 분리** — 방향은 회전(FixedTurn 120°/s), 거리는 보간(FInterpTo). 어떤 급회전에도 경로가 원호가 되어 0점을 지나지 않는다:

```cpp
// [극좌표 접근] 성분(X/Y) 보간은 목표 방향이 크게 돌 때(급회전) 경로가 0점을
// 지나 가구가 몸을 관통한다 — 방향은 회전, 거리는 보간으로 분리해 항상 호를 그린다
const float CurAng = FMath::RadiansToDegrees(FMath::Atan2(CurOff.Y, CurOff.X));
const float DesAng = FMath::RadiansToDegrees(FMath::Atan2(DesOff.Y, DesOff.X));
const float NewAng = FMath::DegreesToRadians(FMath::FixedTurn(CurAng, DesAng, 120.0f * DeltaTime));
const float NewLen = FMath::FInterpTo(CurOff.Size(), DesOff.Size(), DeltaTime, 3.0f);
Anc->InitialOffset.X = NewLen * FMath::Cos(NewAng);
Anc->InitialOffset.Y = NewLen * FMath::Sin(NewAng);
```

③ 정면 복원 기준을 카메라에서 **몸통 실제 방향**(`GetActorRotation().Yaw`)으로 — 같은 날 오전에 카메라 기준으로 통일했던 걸 저녁에 다시 뒤집었다. 카메라는 즉각 점프하는 목표라 복원 경로가 몸을 관통하고, 몸은 카메라를 완속으로 쫓는 중간 매개라 가구가 호를 그리며 따라온다. **카메라 → 몸(완속 추종) → 가구(몸 기준 복원)** 체인.

④ 속도 동조: 1인 가구 회전 상한 2배(180°/s, 들것과 동일 배율), 몸통 회전은 지수 보간의 초반 폭주를 막기 위해 보간 속도 0.4배 + 스텝 상한 180°/s — 몸과 가구가 같은 각속도로 함께 돈다.

## 4. 운반 아웃라인 가림 판정 — 이웃 씬뎁스 비교

**증상**: 운반 중 가구가 몸에 밀착하면, 캐릭터에 가려진 가구의 포커스·운반 링이 **몸 위로 비쳐** 보인다 (X-ray가 아닌 일반 링인데도).

**분석과 해결** (`M_PP_OutlineHLSL` 머티리얼만 수정): 링의 가시부 판정이 커스텀뎁스와 씬뎁스를 비교할 때 여유를 50uu나 줬던 것 — 몸에 밀착한 가구는 가림 깊이 차가 50uu 이내라 전부 "보이는 부분"으로 오판됐다. 판정을 **이웃 지점 씬뎁스 비교**로 바꾸고 여유를 5uu로 조였다. 임박(빨간) 링의 벽 너머 X-ray 기능은 의도된 것이므로 유지.

7/13에 정리한 "커스텀뎁스는 가림을 모른다 — 가시부 한정은 씬뎁스 비교로"의 연장선. 이번엔 그 비교의 **여유값이 판정 해상도를 결정**한다는 걸 배웠다. 여유는 Z-파이팅만 막을 만큼 최소로.

## 5. 시간 알림·핫타임 정리와 위젯 선로딩

게임 피드백 서브시스템(`TCFeedbackSubsystem`) 정리:

- **시간 알림**: 상시 경고·안전바를 제거하고, 5분부터 매 분 "N분 경과했습니다" 3초 토스트로 전환. `LastAnnouncedMinute`는 -1(미초기화)로 두고 Playing 첫 관찰 때 현재 분으로 동기화 — 중간 합류·재시작 시 지난 분들이 몰아서 뜨는 걸 막기 위한 것으로 보인다.
- **핫타임 단순화**: 적재율 진입·종료 조건(`HotTimeStartRatio`/`HotTimeEndRatio`)을 삭제하고 "5분 경과 시 진입, 게임 끝까지 유지"로. 조건이 세 개면 튜닝도 세 배다 — 기획이 확정한 규칙만 남긴다.
- **파손 경고**: 시간 알림과 겹치지 않게 아래로 이동, 로비에서는 텍스트 없이 사운드만.
- **위젯 클래스 선로딩**: 토스트·파손 위젯 클래스를 월드 시작 시 미리 로드 — 5분 시점에 처음 뜰 때의 동기 로드 히치(및 디버거 브레이크) 제거.

## 6. 스테이지 맵 체계 개편 — 진행 자동화와 툰스카이 주야

스테이지 맵 체계를 정리하고 진행을 자동화했다:

- 신규 초반 레벨을 `L_Level1`로 개명(리다이렉터 정리), 기존 레벨은 `L_Level2`. `DT_Stages`의 Stage_2를 L_Level2로 연결하고 `MapsToCook`에 추가 — 패키징 누락 방지.
- **클리어 후 로비 복귀 시 다음 스테이지 자동 선택**. 게임 종료 상태(`bIsGameFinished`)로 복귀했을 때만 진행하고, 일시정지 메뉴의 중도 포기 복귀는 진행하지 않는다. 마지막 스테이지면 유지:

```cpp
// [스테이지 진행] 클리어(게임 종료) 상태로 로비에 복귀하면 다음 스테이지를 기본 선택
const ATeamCarryGameState* GS = World->GetGameState<ATeamCarryGameState>();
if (GS && GS->bIsGameFinished)
{
    FStageInfo NextInfo;
    const int32 NextId = GetSelectedStageId() + 1;
    if (FindStageInfo(NextId, NextInfo))
    {
        SetStageSelection(NextId);
    }
}
```

- `L_Level1`에 툰스카이 적용 + `M_ToonSky`에 태양 고도 연동 주야 체인 추가 — 스테이지별로 태양 각도만 바꾸면 하늘 톤이 낮·노을·밤으로 이어진다. L_Level1 월드세팅 게임모드가 L_Level2와 동일(BP_TeamCarryGameMode)한 것도 확인.

## 오늘 배운 것 정리

1. **분산 판정은 측정 기준부터 통일한다.** 서버는 실제 트랜스폼, 클라는 보간 위치로 같은 반경을 재면 같은 코드가 다른 답을 낸다. 보정(-8 여유)으로 덮지 말고 기준을 통일하라 — 전제가 사라지면 보정은 부작용만 남긴다.
2. **매 틱 다듬는 상태는 이벤트 동기화에 안 실린다.** 그랩·리셋 시점에만 내려보내는 앵커가 서버에서 매 틱 변형되면 클라는 수십 uu 낡은 값으로 판정한다 — 주기 재동기화(스로틀)를 붙인다.
3. **경계에 상주하는 시스템에 하드 컷을 쓰지 마라.** 운반 보행은 리쉬 경계 위에서 평형을 이룬다 — 소프트 숄더(점진 차단)로 바꾸면 벽 체감이 사라진다. 안전망들은 숄더 밖에서만.
4. **기준각 재기록은 모든 파생 기준을 델타 시프트로 함께 옮긴다.** 하나만 재기록하면 나머지가 그랩 시점으로 되감겨 순간 점프가 된다.
5. **"의도 없음 = 제외" 규칙은 의도원이 하나뿐일 때 시스템 전체를 죽인다.** 피동 분류·가중치 제외 같은 다수결 설계는 N=1 경로를 반드시 따로 확인한다.
6. **위치 보간은 성분이 아니라 극좌표로.** X/Y Lerp는 목표가 반대편으로 돌 때 0점(중심)을 관통한다 — 방향은 회전, 거리는 보간으로 분리하면 항상 호를 그린다. 회전 의도의 선행 제한(±45°)과 묶으면 급회전에도 안전하다.
7. **깊이 비교의 여유값이 판정 해상도다.** 50uu 여유는 몸에 밀착한 가구의 가림을 통째로 놓친다 — 여유는 Z-파이팅만 막는 최소(5uu)로.
8. **주기 알림·상태 진입 로직은 초기값을 '현재'로 동기화한다.** 미초기화(-1) → 첫 관찰 때 현재 분으로 맞추면 중간 합류에 몰아치기가 없다.
