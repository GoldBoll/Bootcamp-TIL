## 1. CS 32 방화벽 — 발표 + 파일 보강

- 모의면접 "방화벽이 무엇이며 어떻게 동작하는지" 발표. 30(TCP/UDP) → 31(Socket) → 32(Firewall)로 네트워크 트랙 마무리.
- 공부하며 비어 있던 부분을 보강:
  - **트래픽** = 네트워크를 오가는 패킷의 흐름. 방화벽은 그 패킷의 5-tuple(봉투)을 검사.
  - **OSI 계층** L3(IP 주소)·L4(포트)·L7(내용물)을 택배 비유로 정리 — 계층이 높을수록 깊이 보지만 느림.
  - **가정용 공유기 = 작은 방화벽 + NAT** — 평소 인바운드 자동 차단. 밖에서 내부 기기로 접속하려면 **포트포워딩**(지정 포트만 전달)이나 **공유기 DMZ**(한 기기 모든 포트 노출, 위험).
  - 기업용 DMZ(격리 구역) vs 공유기 DMZ(전체 노출)는 이름만 같고 동작이 정반대임을 명시.
- 모의면접 답변 다이어트: 외운 리스트 느낌의 '종류 4종' 문단과 '요약' 문단을 본문에서 제거(꼬리질문·본문에 이미 상세). 답변은 default deny까지 말하고 Zero Trust로 마무리.

## 2. CS 33 UObject — 네트워크에서 언리얼로 트랙 전환

- 30~32(순수 CS·네트워크)에서 **언리얼 엔진 C++ 도메인**으로 넘어가는 첫 주제로 UObject 선정.
- 다룬 핵심:
  - **리플렉션 시스템** — `UCLASS`/`UPROPERTY`/`UFUNCTION` + UHT(Unreal Header Tool)가 `.generated.h` 생성.
  - **CDO(Class Default Object)**·UClass 메타데이터.
  - **GC(가비지 컬렉션)** — `UPROPERTY` 참조 그래프·루트 셋. `UPROPERTY()` 안 붙이면 GC가 못 보고 댕글링 위험.
  - **UObject vs AActor vs UActorComponent** 위치 관계, 클래스 계층(UObject → AActor → APawn → ACharacter).
  - 표준 C++ `new`/`delete` 대신 `NewObject`/`CreateDefaultSubobject`를 쓰는 이유.
- **회귀 다리** — 그동안 쌓은 C++ 객체 모델(04 OOP, 05·08 vtable, 06 가상 소멸자, 11 스마트포인터, 03 new vs malloc)이 "언리얼이 **왜 표준 C++ 위에 자기 객체 시스템을 한 겹 더 올렸나**"를 이해하는 배경.
- 발표는 수(06-03) 휴무 후 **목(06-04)**.

## 3. Ch4 "TRACE" 컨셉 개정

어제(06-01) 잡은 컨셉의 두 굵은 결정을 단순화·정정했다.

- **보상: 현상금 경제(Time Bounty) → 이진 승패**
  - 8주 스코프에 별도 보상 경제까지 설계·구현하면 부담이 크고 초점이 흐려진다고 판단.
  - 범인의 소극성 문제를 *보상*이 아니라 **승리 조건의 구조**로 해결 — "배신자가 가만히 있으면 시민이 미션을 끝내 이긴다 → 이기려면 반드시 사보타주해야 함".
- **네트워킹: 리슨 서버 → 데디케이트 서버**
  - 부트캠프 커리큘럼으로 **학습하며 구축**하므로 막연한 리스크가 아니라 학습으로 흡수되는 리스크.
  - 그 결과 1순위 리스크를 *네트워킹 → 코어 게임플레이 루프(은닉/수색/감식/검거)의 재미*로 이동.
- 블로그 글(`_posts`)·TIL 양쪽을 개정 기준으로 동기화.

## 4. 블로그 TIL 발행 파이프라인 구축 (오늘의 메인)

- **종합본 + 발행본 쌍 구조 확립**
  - 종합본 `til/YYYY-MM/YYYY-MM-DD.md` — 상세 원본 기록, 빌드에서 제외.
  - 발행본 `_posts/YYYY-MM-DD-til-<주제슬러그>.md` — 다듬은 공개용, Jekyll 렌더링.
  - `_config.yml`의 `exclude`에 원본 월 폴더(2~6월)를 넣어 사이트엔 발행본만 노출.
- **TIL 제목 51개 전부 주제 포함으로 일괄 변경** — `[TIL] YYYY-MM-DD — <주제>`. 날짜만 있던 제목에 그날 핵심 학습 주제를 박아, 목록만 봐도 내용이 보이게.
- **통제 태그 어휘(controlled vocabulary)** — `_data/tag_vocab.yml`의 canonical 태그만 허용, CI의 `normalize-tags.ps1 -Strict`가 미등록 태그에서 빌드를 실패시킴. 새 키워드는 vocab에 먼저 등록 후 사용.
- **til-agent에 패턴 고정** — 앞으로 "TIL 정리해줘" 하면 종합본+발행본 쌍을 자동 생성, 제목 주제화·태그 린트·신규 월 exclude까지 규칙화.
- 부수 작업 — 커밋의 `Co-Authored-By` 트레일러 제거(amend + force-with-lease), GitHub Pages 동작(레포 비공개 vs 사이트 공개) 확인.

## 오늘 배운 것 정리

1. **기록 인프라도 자산이다** — 글이 쌓일수록 "제목만 봐도 뭘 했는지" 보이게 하는 작은 규칙(제목에 주제)이 50여 개 글의 검색·회고 가치를 바꾼다.
2. **원본과 발행본을 분리** — 상세 종합본(빌드 제외)과 다듬은 발행본(공개)을 쌍으로 두면 기록의 충실함과 공개본의 가독성을 동시에 잡는다.
3. **가드레일은 자동화로** — 통제 태그 어휘 + CI 린트로 오타·난립 태그를 빌드 단계에서 차단. 사람이 규칙을 외우는 대신 시스템이 강제하게.
4. **GitHub Pages는 "레포 비공개 ≠ 사이트 비공개"** — private 레포 Pages는 유료 플랜에서만 빌드되고, 그래도 사이트 자체는 공개. 진짜 접근 제한은 Enterprise(Private Pages).
5. **승리 조건 = 행동 설계** (Ch4) — 범인 소극성을 보상 경제(복잡)로 풀려다 이진 승패의 승리 조건 구조(단순)로 해결. 단순한 규칙이 같은 압박을 만든다면 그게 낫다.
6. **리스크는 종류를 구분해 다룬다** (Ch4) — 학습으로 흡수 가능한 리스크(데디케이트 서버 = 부트캠프 커리큘럼)는 1순위에서 내리고, 학습으로 못 메우는 리스크(코어 루프 재미)를 1순위로 올린다.
