오전에는 AI Literacy 강의, 오후에는 C++ 코딩테스트 강의(챕터 2-1 알고리즘 효율성, 챕터 2-3 입출력 데이터 다루기)를 들었다. 코테 풀이에 바로 쓰일 내용은 시간복잡도 감각과 입출력 파싱이라 그 둘을 중심으로 정리하고, AI Literacy와 튜터님과 나눈 이야기는 뒤에 붙인다.

## 알고리즘 효율성 (챕터 2-1)

알고리즘 성능은 절대 시간이 아니라 **연산 횟수** 기준으로 판단한다. PC 성능은 제각각이지만, 입력이 커질수록 결국 연산 수의 증가 추이가 성능을 결정하기 때문이다. 반복문 횟수만이 아니라 비교·대입·산술 연산이 전부 비용이고, 대용량 배열 비교 같은 것도 무시할 수 없다 — 실제 코테에서 자주 걸리는 지점이다.

입력이나 탐색 위치에 따라 최선/최악의 경우가 갈리는데, 코테는 항상 **최악 기준(Big-O)**으로 판단한다. 빅오는 점근적 표기법(입력이 충분히 클 때의 증가 추세만 보고 상수·저차항을 제거하는 방식)으로 최악 기준의 상한을 나타내며, 최고차항만 남겨 가장 타이트한 상한을 고른다. 예: 3N²+2N → O(N²).

시간을 가늠할 때는 **1초 ≈ 1억 연산**으로 잡는다. N=1,000,000이면 O(N log N) 이하로 설계해야 한다는 계산이 나온다.

복잡도별 대표 패턴은 코드로 봤다.

**O(N) — 선형 탐색**: 배열 전수 탐색이라 최악 O(N).

```cpp
for (int i = 0; i < size; i++)
    if (arr[i] == target) return i;
```

**O(N²) — 2차원 순회**: 이중 반복문.

```cpp
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        sum += arr[i][j];
```

**O(log N) — 절반 감소**: 반복마다 범위가 절반으로 줄어 로그로 증가.

```cpp
while (N > 1) { N /= 2; }
```

**O(2^N) — 모든 조합**: 완전 탐색/브루트포스, N이 커지면 폭발적으로 증가.

```cpp
for (int a = 0; a < 2; a++)
    for (int b = 0; b < 2; b++)
        for (int c = 0; c < 2; c++) {}
```

적용 전략은 하나로 요약된다. **입력 최대값을 먼저 확인하고 허용 복잡도를 역산한 뒤 구현에 들어간다.** 시간복잡도 상한을 정하는 게 구현보다 먼저다.

## 입출력 데이터 다루기 (챕터 2-3)

코딩테스트는 알고리즘보다 **입력 파싱**에서 시간을 잃는 경우가 많다. 공백·구분자·진법 등 다양한 형식을 빠르게 처리하는 습관이 필요하다.

먼저 반올림/올림/내림. round / ceil / floor의 차이를 정확히 알아야 하는데, 특히 음수 처리 방식이 달라 예외 케이스 대비가 필요하다. round는 0.5를 away from zero(0에서 먼 쪽) 기준으로 반올림한다.

```cpp
round(-2.5); // -3
```

ceil은 항상 위쪽 정수, floor는 항상 아래쪽 정수다.

```cpp
ceil(-3.2);  // -3
floor(-3.7); // -4
```

stringstream은 문자열을 **입력 스트림처럼 처리**할 수 있게 해준다. cin과 동일한 `>>` 방식으로 데이터를 추출한다.

공백 기준 분리는 `>>` 연산자가 자동으로 토큰화해 준다.

```cpp
stringstream ss;
ss >> a >> b >> c;
```

특정 문자 기준 분리는 getline + 구분자.

```cpp
while (getline(ss, token, ',')) {}
```

진법 변환도 stringstream으로 된다. 10진수 → 16진수는 hex 조작자를 넣어 출력하고,

```cpp
ss << hex << decimal;
```

16진수 → 10진수는 hex 설정 후 `>>`로 파싱한다.

```cpp
ss >> hex >> decimal;
```

결론: 파싱/형변환을 직접 구현하지 말고 **표준 라이브러리를 활용**한다. 시간이 줄고, 실수가 줄고, 가독성이 좋아진다.

## AI Literacy 강의 요약

프롬프트 설계 기법으로 **RAG**(외부/내부 자료를 검색한 뒤 생성해 정확도를 높이는 방식), **Zero-shot / Few-shot**(예시 없이 요청 vs 예시를 줘서 형식을 고정), **CoT**(추론 과정을 드러내 검증 가능성을 확보 — 실무에서는 요약된 근거 제시 권장)를 배웠다. 출력이 나오면 제약을 재확인하고 반례를 점검하는 검증 루틴을 돌리면 오답이 줄어든다. "찾아줘"와 "찾아와"처럼 명령어 강도 차이도 결과 완결성에 영향을 준다 — 명령형 표현이 구체적 실행 요구를 강화한다.

핵심은 **Structured Prompt**: Role/Goal/Constraints/Format을 명시하면 품질이 안정된다.

- **예시 1 — 기술 TIL 요약용**: Role은 게임프로그래밍 취준생, Goal은 오늘 배운 내용 요점 정리, Constraints는 각 항목 2줄 이하·굵은 키워드·리스트 형식, Format은 Markdown 목록
- **예시 2 — 코딩테스트 문제 분석용**: Role은 알고리즘 분석가, Goal은 문제 풀이 전략 설계, Constraints는 시간복잡도 명시·예외 2개 포함, Format은 단계별 분석 구조

활용 포인트는 네 가지다. ① 역할 명확화 — 결과의 톤과 관점을 고정하기 위해 면접용/보고서용 등 목적에 맞는 정체성을 준다. ② 목표 구체화 — "정리해줘" 대신 "면접 제출용 요약 작성"처럼 산출물 목적을 정의한다. ③ 제약 조건 설정 — 분량·형식·강조 방식을 지정하면 일관성이 생기고 할루시네이션이 줄어 검증도 쉬워진다. ④ 출력 형식 고정 — Markdown/표/코드블록을 지정하고, 반복 사용하면 템플릿화해 생산성을 올린다.

## 튜터님과의 대화 — 키워드 RnD 학습법

튜터님이 권한 학습법은 강의를 단순 요약하지 말고, 키워드를 뽑아 재조합해 **내 언어로 재구성**하라는 것이었다. 복붙 정리보다 개념을 연결하는 과정에서 사고가 확장되고, 키워드를 재배열하다 보면 원리 중심으로 구조화되면서 지식이 내 것이 된다. 질문이 변형돼도 대응할 수 있는 설명력이 생기니 면접 대비에도 직결된다.

적용 순서는 이렇다. ① 강의/문서에서 핵심 개념 5~10개 추출 → ② 인과관계·흐름 중심으로 새 목차 구성 → ③ 프로젝트/코테 사례에 직접 매핑 → ④ "설명 → 반례 질문 → 보완"을 반복하며 검증. 단, 키워드만 남기면 맥락이 사라질 위험이 있으니 핵심 예시 1개는 꼭 포함한다. 매일 TIL에 한 번씩 적용해서 학습 자산으로 쌓아가기로 했다.

> **오늘 배운 것** — 코테 성능은 절대 시간이 아니라 연산 횟수(최악 기준 Big-O)로 판단하고, 1초 ≈ 1억 연산 기준으로 입력 최대값에서 허용 복잡도를 역산한 뒤 구현에 들어간다는 순서를 잡았다. 입력 파싱은 stringstream 등 표준 라이브러리로 처리해 시간과 실수를 줄인다.
