## 작업 목표

오늘은 `VOIDBaseCharacter`에 탑다운 카메라를 붙이고, WASD 이동을 카메라 시점 기준으로, Space를 점프로 연결했다. 레거시 입력을 걷어내고 Enhanced Input System(키 입력을 InputAction·InputMappingContext 에셋으로 관리하는 UE5의 입력 시스템)만 쓰는 것이 목표였다.

---

## 구현 내용

### 1. 카메라 컴포넌트 추가 (`VOIDBaseCharacter`)

카메라는 `SpringArmComponent`(캐릭터와 카메라 사이 거리를 유지해 주는 지지대 컴포넌트)와 `CameraComponent` 조합으로 구성했다. `CameraBoom`은 RootComponent에 부착하고 길이 800, Pitch -60도를 줘서 탑다운 각도를 만들었다. `FollowCamera`는 CameraBoom 소켓에 붙이고 폰 컨트롤 회전을 꺼서, 카메라가 캐릭터를 따라다니되 회전하지는 않는 고정 탑다운 시점이 됐다.

### 2. Enhanced Input 클래스 구조

| 클래스 | 부모 | 역할 |
| --- | --- | --- |
| `USC_MoveAction` | `UInputAction` | ValueType = Axis2D (Vector2D), WASD 이동용 |
| `USC_JumpAction` | `UInputAction` | ValueType = Boolean, Space 점프용 |
| `USC_InputMappingContext` | `UInputMappingContext` | 두 Action을 내부에 자동 생성, WASD+Space 매핑 자동 구성 |

### 3. WASD 매핑 구성 (`USC_InputMappingContext::BuildDefaultMappings`)

Axis2D 하나로 WASD를 전부 받으려면 W/S 입력을 Y축으로 돌려줘야 해서 SwizzleAxis(입력 축 순서를 바꿔주는 모디파이어)를 썼다.

| 키 | 방향 | 모디파이어 |
| --- | --- | --- |
| W | 앞 (Y +1) | SwizzleAxis YXZ |
| S | 뒤 (Y -1) | SwizzleAxis YXZ + Negate |
| D | 오른쪽 (X +1) | 없음 |
| A | 왼쪽 (X -1) | Negate |
| Space | 점프 | 없음 |

### 4. 카메라 기준 이동 로직

```cpp
const FRotator CameraYaw(0.0f, CameraBoom->GetComponentRotation().Yaw, 0.0f);
const FVector ForwardDir = FRotationMatrix(CameraYaw).GetUnitAxis(EAxis::X);
const FVector RightDir   = FRotationMatrix(CameraYaw).GetUnitAxis(EAxis::Y);

AddMovementInput(ForwardDir, Input.Y);
AddMovementInput(RightDir,   Input.X);
```

카메라 회전에서 Yaw만 뽑아 수평 이동 방향으로 변환했다. 이렇게 하면 나중에 카메라가 회전해도 이동 방향이 자동으로 따라온다.

## 시행착오

### 시행착오 1 — VOIDPlayerCharacter vs VOIDBaseCharacter

처음에 `VOIDPlayerCharacter`에 입력 코드를 작성했는데, 실제로 쓰이는 클래스는 `VOIDBaseCharacter`였다. 코드를 옮기는 것으로 해결했지만, 작업 전에 어떤 클래스가 실제로 스폰되는지부터 확인했어야 했다.

### 시행착오 2 — BuildDefaultMappings() 수동 호출 문제

`USC_InputMappingContext`는 `UObject` 기반 데이터 에셋이라 블루프린트의 Construction Script 같은 게 없다. 그래서 `BuildDefaultMappings()`를 명시적으로 불러주지 않으면 에디터에서 매핑이 보이지도 않고 런타임에도 동작하지 않았다. `PostLoad()`(에셋이 로드될 때 호출)와 `PostEditChangeProperty()`(에디터에서 프로퍼티가 바뀔 때 호출)를 오버라이드해 자동으로 호출되게 했다.

```cpp
void USC_InputMappingContext::PostLoad()
{
    Super::PostLoad();
    BuildDefaultMappings();
}

#if WITH_EDITOR
void USC_InputMappingContext::PostEditChangeProperty(FPropertyChangedEvent& e)
{
    Super::PostEditChangeProperty(e);
    BuildDefaultMappings();
}
#endif
```

### 시행착오 3 — Enhanced Input 경고 발생

`Axis and Action mappings are now deprecated, please use Enhanced Input Actions and Input Mapping Contexts instead.` 경고가 계속 떴다. 원인을 추적해 보니 `DefaultMappingContext`와 `MoveAction` UPROPERTY를 블루프린트에서 수동 할당하지 않아 null 상태였고, Enhanced Input이 실제로 등록되지 않은 채 레거시 입력 경로로 빠지고 있었다. 생성자에서 `CreateDefaultSubobject`로 직접 만들어 주는 방식으로 null이 생길 여지를 없앴다.

```cpp
// VOIDBaseCharacter 생성자
InputMappingContext = CreateDefaultSubobject<USC_InputMappingContext>(TEXT("InputMappingContext"));
```

### 시행착오 4 — DefaultInput.ini 확인

혹시 프로젝트 설정 문제인가 싶어 `DefaultInput.ini`도 확인했다.

- `DefaultPlayerInputClass=/Script/EnhancedInput.EnhancedPlayerInput`
- `DefaultInputComponentClass=/Script/EnhancedInput.EnhancedInputComponent`

설정은 이미 Enhanced Input으로 잡혀 있었다. 결국 문제는 설정이 아니라 코드 레벨의 null 참조였다.

## 최종 구조 요약

```
AVOIDBaseCharacter
├── USpringArmComponent (CameraBoom)
├── UCameraComponent (FollowCamera)
└── USC_InputMappingContext (InputMappingContext)
    ├── USC_MoveAction (MoveAction) — Axis2D, WASD 자동 매핑
    └── USC_JumpAction (JumpAction) — Boolean, Space 자동 매핑
```

- 블루프린트에서 아무것도 할당하지 않아도 WASD 이동 + Space 점프 자동 동작
- `Build.cs`에 `EnhancedInput` 모듈 추가 필요

> **오늘 배운 것** — UObject 기반 데이터 에셋에는 Construction Script가 없어서 초기화 코드를 `PostLoad()`·`PostEditChangeProperty()`에서 직접 호출해야 한다는 것, 그리고 Enhanced Input 관련 프로퍼티가 null이면 경고만 남기고 조용히 레거시 입력 경로로 빠진다는 것을 배웠다.
