## 시뮬레이션 — 좌표와 행렬 (챕터 3-4)

시뮬레이션 문제의 기본은 2차원 배열에서 y는 행, x는 열이라는 좌표 표현이다. 이동은 dy, dx 오프셋 배열로 4방향/8방향 탐색을 하드코딩 없이 처리한다. 여기에 문제마다 반복해서 나오는 변환 규칙들이 있다.

- 좌우 대칭: (y, x) -> (y, (N-1)-x)
- 상하 대칭: (y, x) -> ((N-1)-y, x)
- 90도 회전: (y, x) -> ((N-1)-x, y)
- 정방향 대각선: (y+1, x+1), 역방향 대각선: (y+1, x-1)
- 행렬 덧셈: 같은 위치 원소끼리 연산 / 행렬 곱셈: A의 행과 B의 열 내적

이걸 문제 세 개에 직접 적용해 봤다.

문제 64 달팽이 수열은 start/end 경계를 좁혀가며 외곽부터 채우는 경계 수축 방식으로 풀었다.

```cpp
while (start_row <= end_row && start_col <= end_col) {
  // 상->우->하->좌 순서로 채우고 경계 갱신
}
```

문제 65 이진 변환은 0 제거 횟수를 누적하면서, 남은 1의 개수를 이진 문자열로 바꾸는 과정을 반복한다.

```cpp
removedZeros += count(s.begin(), s.end(), '0');
int onesCount = count(s.begin(), s.end(), '1');
```

문제 69 캐릭터 좌표는 보드 경계값(±board/2)을 먼저 체크하고 이동을 적용하는 게 전부다.

```cpp
if (s=="up" && v[1] < board[1]/2) v[1]++;
else if (s=="left" && v[0] > -board[0]/2) v[0]--;
```

| 주제 | 대표 복잡도 | 메모 |
| --- | --- | --- |
| dy/dx 인접 순회 | O(방향 수) | 4방향/8방향은 상수 |
| 달팽이 수열 n*n 채우기 | O(n^2) | 모든 칸 1회 방문 |
| 이진 변환 반복 | 문자열 길이 의존 | count + 문자열 재구성 반복 |
| 캐릭터 좌표 | O(keyinput 길이) | 입력 1개당 상수 연산 |

자습하면서 느낀 건, 시뮬레이션은 공식을 외우는 것보다 좌표 변환 규칙을 코드로 옮기는 감각이 더 중요하다는 점이다. 특히 dy/dx와 경계 체크를 템플릿처럼 고정해두면 구현 속도와 정확도가 같이 올라간다.

## 스택과 큐 (챕터 3-5·3-6)

스택은 LIFO(Last In First Out) — 가장 나중에 넣은 데이터가 가장 먼저 나온다. push로 삽입, pop으로 최상단 제거, top으로 최상단 조회이며, ADT 관점에서는 연산(인터페이스) 중심으로 추상화된 자료구조다. 브라우저 뒤로가기가 딱 스택 모델이다 — "최근 방문 페이지를 제거하고 이전 페이지로 이동"이니까.

```cpp
#include <stack>
stack<string> history;
history.push("A");
history.push("B");
history.push("C");

cout << history.top() << endl; // C
history.pop();
cout << history.top() << endl; // B
```

함수 호출/복귀 흐름도 LIFO라서 호출 스택 개념을 직관적으로 보여준다.

```cpp
void B(){ cout << "B 호출" << endl; cout << "B 종료" << endl; }
void A(){ cout << "A 호출" << endl; B(); cout << "A 종료" << endl; }
int main(){ cout << "main 호출" << endl; A(); cout << "main 종료" << endl; }
```

큐는 반대로 FIFO(First-In First-Out) — 먼저 들어간 데이터가 먼저 나온다. push()는 뒤(rear)에 삽입, pop()은 앞(front) 제거, front()는 가장 먼저 들어온 데이터 조회, empty()는 비었는지 검사다. 공용 프린터나 매표소 대기줄처럼 요청 순서대로 처리되는 상황이 큐다.

```cpp
#include <queue>
queue<string> q;
q.push("PC-B");
q.push("PC-C");
q.push("PC-A");
while(!q.empty()){
  cout << q.front() << endl;
  q.pop();
}
```

```cpp
queue<string> ticketLine;
ticketLine.push("Alice");
ticketLine.push("Bob");
ticketLine.push("Charlie");
while(!ticketLine.empty()){
  cout << ticketLine.front() << " got the ticket." << endl;
  ticketLine.pop();
}
```

두 자료구조 모두 push/pop/top(front) 연산이 O(1)이다. 결국 문제를 볼 때 "가장 최근 것을 처리해야 하나(스택), 들어온 순서대로 처리해야 하나(큐)"라는 시그널을 먼저 찾는 습관이 자료구조 선택 속도를 결정한다고 느꼈다. 그리고 top()/front() 호출 전에 empty() 체크를 습관화해야 구현 실수가 줄어든다.

## 자습 — 이전 프로젝트 마이그레이션 점검

오늘 자습에서는 기능 추가보다 기초 안정화를 우선했다. 마이그레이션 이후에는 동작만 되면 끝이 아니라 참조 구조까지 확인해야 한다는 걸 이번에 체감했다. 점검한 항목은 다음과 같다.

- 마이그레이션 후 레퍼런스 끊김(깨진 참조)이 없는지 레벨/블루프린트 단위로 열어서 확인
- 폴더 구조와 네이밍 규칙이 뒤섞이지 않았는지(임시 폴더, 중복 에셋, 한글/공백 이름) 정리 기준 적용
- 리다이렉터(Redirector, 에셋 이동 후 옛 경로에 남는 참조 안내 파일) 정리 후, 이동/이름변경한 에셋이 실제 경로로 정상 참조되는지 점검
- 블루프린트 컴파일 경고/오류를 한 번에 넘기지 않고, 오늘 만든 수정사항부터 우선 해결
- 프로젝트 버전/플러그인 의존성 차이로 생길 수 있는 충돌 가능성 확인

다음 작업부터는 파일 이동/리네임 후 바로 리다이렉터 정리를 루틴으로 고정할 생각이다.
