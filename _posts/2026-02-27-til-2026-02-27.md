이전 프로젝트를 새 환경으로 옮기면서 겪은 환경 문제를 해결하고, 옮긴 김에 작업물 전체를 복기했다.

## Visual Studio 버전 문제 — UE 5.5는 2022까지만

**증상**: PC에는 VS 2026이 설치돼 있었는데, 언리얼 에디터에서 C++ 클래스를 생성하려고 하니 2022 설치를 요구했다. UE 5.5.4는 Visual Studio 2022까지만 공식 지원이라, 현시점에서는 2026으로 언리얼 C++ 개발이 불가능하다.

**원인**: 언리얼 엔진은 지원 목록에 있는 MSVC 툴체인(컴파일러·링커 등 빌드 도구 묶음) 버전만 인식한다. VS 2026은 UE 5.5 기준으로 아직 툴체인 검증이 끝나지 않은 상태라, C++ 프로젝트 빌드와 클래스 생성에는 VS 2022가 필수다.

**해결**:

1. Visual Studio 2022 설치
2. 설치 옵션에서 체크
    - Desktop development with C++
    - MSVC v143 toolset
    - Windows 10/11 SDK
3. UE 에디터 → Editor Preferences → Source Code → **Visual Studio 2022 선택**

VS 2022와 2026은 동시 설치가 가능해서 2026을 지울 필요는 없다. 다만 UE 작업, 적어도 캠프 기간에는 2022를 기본으로 쓰기로 했다.

## 프로젝트 제너레이트로 튕김 해결

프로젝트를 옮긴 뒤 에디터가 튕기는 현상이 있었는데, 중간 산출물을 지우고 프로젝트 파일을 다시 제너레이트해서 전체를 최신화하니 사라졌다. 삭제 대상은 다섯 개.

- .vs
- Binaries
- Intermediate
- Saved
- .sln (솔루션 파일)

삭제 후 `.uproject` 우클릭 → Generate Visual Studio project files를 실행하면 된다.

## 이전 프로젝트 작업물 확인 및 코드 정리

오늘의 목표는 이전 프로젝트 작업물 전체를 점검하고, 플레이어 동작 로직과 C++ 솔루션 코드 구조를 다시 확인해서 필요한 기능을 개인 프로젝트에 재활용할 준비를 하는 것이었다.

**일일 작업 내역 확인** — 지스타 시즌2 작업 내역을 정리했다. 애니메이션, AI, 연출, 트랜스폼 등 기능별 작업 기록과 BT(Behavior Tree, AI 행동을 트리 구조로 설계하는 방식)/AI 관련 작업 이력, 수정·개선 이력을 훑었다. 애니메이션 연동 구조가 있고 AI 추적·패턴 작업 기록, 트랜스폼/상호작용 관련 내역도 남아 있어, 플레이 로직과 연관된 기능이 다수 포함돼 있었다.

**C++ 솔루션 코드 확인** — AI 클래스 구조, 입력 처리 로직, 상태 전환 구조, Tick/Update 흐름, 컴포넌트 구성 방식을 확인했다. 전체적으로 입력 → 상태 처리 → 애니메이션 반영으로 이어지는 구조였고, 클래스 분리도 비교적 명확했다. 재사용할 만한 부분은 이동 로직, 상태 기반 처리 방식, 기본 캐릭터 컨트롤 흐름이다.

**플레이 정상 동작 확인** — [플레이 확인 영상](https://drive.google.com/file/d/1uiQHyp5eqrygsp1AnYJYlJV3n6ZwMd_3/view?usp=sharing)

캐릭터 이동, 카메라 동작, AI 배치, 에셋·머티리얼 적용까지 전부 정상이었다. 핵심 플레이 기능이 살아 있으니 코드는 재사용 가능한 상태다.

**재활용 계획** — Player 기본 클래스 구조, 이동 처리 로직, 상태 기반 업데이트 구조, 일부 AI 동작 로직을 가져올 예정이다. 다만 그대로 옮기지 않고 개인 프로젝트 구조에 맞게 리팩토링하면서 불필요한 종속성 제거, 네이밍 규칙 통일, 모듈 단위 재정리를 함께 진행한다.

## 오늘의 정리

이전 작업물의 전반적인 구조를 복기하며 코드 흐름을 다시 이해했고, 정상 동작 확인까지 마쳤다. 개인 프로젝트에 적용할 준비가 끝났다.
