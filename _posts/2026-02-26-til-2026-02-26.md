코딩테스트 강의 이론 복습. 오늘의 본론은 챕터 3-1 재귀함수라 먼저 정리하고, 이어서 들은 2-4 STL과 2-5 알고리즘 효율성은 표 중심으로 압축해 뒤에 붙인다.

## 재귀함수 (챕터 3-1)

재귀 설계의 뼈대는 두 가지다. 문제 크기를 줄이는 설계가 핵심이고, 시간복잡도는 호출 트리 구조로 판단한다. 순서상으로는 반드시 **기저 조건부터** 설계한다.

| 구성 | 목적 | 실수 시 문제 |
| --- | --- | --- |
| **기저 조건(Base Case)** | 종료 보장 | 무한 재귀 |
| **재귀 단계(Recursive Step)** | 문제 축소 | 호출 깊이 과다 |

```cpp
if (n == 0) return 1;
return n * f(n - 1);
```

### 재귀 호출과 스택 메모리

호출마다 스택 프레임(함수 호출 정보를 담는 메모리 단위)이 하나씩 쌓인다. 그래서 공간복잡도는 **O(호출 깊이)** — 깊이가 N이면 공간도 O(N)이다. 깊이가 10^5를 넘어갈 수 있으면 위험하니 반복문 전환을 고려한다.

### 단순 재귀 vs 메모이제이션

| 방식 | 시간복잡도 | 특징 |
| --- | --- | --- |
| 피보나치 단순 재귀 | O(2^N) | 중복 호출 |
| 메모이제이션 | O(N) | 결과 저장 |

fibo(n-1) + fibo(n-2)는 같은 값을 여러 번 다시 계산해서 호출 수가 지수로 늘어난다. 계산 결과를 배열에 저장해 두면(메모이제이션) O(N)으로 떨어진다.

```cpp
if (memo[n] != -1) return memo[n];
memo[n] = f(n - 1) + f(n - 2);
```

DP(동적 계획법)로 전환할 수 있는 형태이며, memo 배열 초기화를 빼먹지 않는 게 포인트다.

### DFS: 재귀 vs 반복(Stack)

| 구현 | 시간 | 공간 |
| --- | --- | --- |
| 재귀 DFS | O(V+E) | O(depth) |
| stack DFS | O(V+E) | O(V) |

재귀는 콜 스택을 **암묵적 스택**으로 쓰는 것이고, 반복 구현은 **명시적 stack**을 쓴다.

```cpp
void DFS(int node) {
    visited[node] = true;
    for (auto next : graph[node])
        if (!visited[next]) DFS(next);
}
```

visited 처리 순서가 중요하고, 그래프 깊이가 크면 반복 구현을 권장한다.

### 지수 연산 최적화 (분할 정복)

| 방식 | 시간복잡도 |
| --- | --- |
| 단순 재귀 pow | O(N) |
| 분할 정복 pow | O(logN) |

N이 짝수면 pow(X, N) = pow(X, N/2)²로 문제 크기를 절반씩 줄이는 게 핵심 아이디어다.

```cpp
double half = pow(x, n / 2);
return (n % 2 == 0) ? half * half : half * half * x;
```

N==0 기저 조건을 반드시 두고, long long 오버플로우를 주의한다.

### 재귀가 맞는 문제, 아닌 문제

분할 정복(병합정렬, 퀵정렬)이나 트리/그래프 탐색처럼 구조가 자연스럽게 분기되는 문제는 재귀가 효율적이다. 반대로 단순 반복 누적 문제나 깊이가 큰 선형 구조는 재귀로 짤 이유가 없다.

시간복잡도 판단 기준은 호출 패턴으로 잡는다. 호출이 1개씩 감소하면 O(N), 2개씩 분기하면 O(2^N), 크기가 절반씩 줄면 O(logN). 실제 예로 fibo 단순 재귀는 O(2^N), pow 분할 정복은 O(logN), DFS는 O(V+E)다.

### 실전 체크리스트

- 깊이 최대치 계산 먼저
- 중복 호출 여부 확인
- 메모이제이션 가능 여부 판단
- 스택 초과 가능성 점검
- 가능하면 반복문 전환 고려

## STL 복습 (챕터 2-4)

STL은 `컨테이너 + 반복자 + 알고리즘`으로 구성되며, 알고리즘과 컨테이너를 **분리 설계**한 것이 유연한 재사용의 핵심이다. 템플릿 기반(Generic Programming)이라 int, string, 커스텀 클래스 등 자료형에 독립적으로 쓸 수 있다. 코테 관점의 결론은 하나 — **자료구조 선택이 곧 시간복잡도 설계의 시작**이다.

### vector — 동적 배열, 코테 1순위

| 연산 | 시간복잡도 | 유의점 |
| --- | --- | --- |
| `push_back()` | O(1) (평균) | capacity 초과 시 O(N) |
| `insert()` (중간) | O(N) | 원소 밀림 발생 |
| `clear()` | O(N) | 전체 삭제 |
| `[]` 접근 | O(1) | 인덱스 기반 접근 가능 |

핵심 메서드는 push_back, insert(pos, value), reserve(n)(재할당 방지), size/capacity, clear.

```cpp
vector<int> v;
v.reserve(100000); // 대량 입력 대비
v.push_back(1);
v[0] = 10;
```

입력 개수를 예측할 수 있으면 reserve를 먼저 부르고, 중간 삽입이 많으면 deque를 고려한다. 인덱스 접근이 필요하면 vector가 최적.

### set — 정렬 + 중복 제거

내부는 Red-Black Tree(자가 균형 이진 탐색 트리)라 삽입/삭제가 O(logN), 중복 불가, 자동 오름차순 정렬. 핵심 메서드는 insert/erase/find/clear.

```cpp
set<int> s;
s.insert(3);
s.erase(3);
```

자동 정렬이라 별도 sort가 필요 없다. 중복을 허용하려면 multiset, 정렬 없이 탐색만 필요하면 unordered_set. 인덱스 접근은 불가.

### map — Key-Value

삽입/삭제/탐색 모두 O(logN), 반복자 삭제는 평균 O(1). 핵심 메서드는 `m[key]`, `m.at(key)`, insert, erase, find.

```cpp
map<string, int> m;
m["A"] = 1;    // 없으면 생성
m.at("A") = 2; // 없으면 예외
m.erase("A");
```

`[]`는 키가 없으면 자동 생성해서 실수로 값이 추가될 수 있으니 존재 확인은 find()로 한다. 단순 키 집합이면 set을 쓰고, 키는 명확한 타입으로(float 지양).

### 반복자와 algorithm 헤더

알고리즘 함수들은 반복자(begin/end, rbegin/rend)를 통해 작동한다.

```cpp
for (auto it = v.begin(); it != v.end(); ++it)
    cout << *it;
```

erase 후 반복자 무효화를 주의하고, range-based for가 간결하고 안전하다.

자주 쓰는 함수는 sort(정렬), find(탐색), count(개수), unique(중복 제거 — 정렬 후 사용).

```cpp
sort(v.begin(), v.end());
auto it = find(v.begin(), v.end(), 5);
```

사용자 정의 정렬은 lambda로.

```cpp
sort(v.begin(), v.end(), [](int a, int b) {
    return a > b;
});
```

### 실전 선택 기준

| 상황 | 추천 컨테이너 |
| --- | --- |
| 인덱스 접근 | vector |
| 정렬 + 중복 제거 | set |
| 키-값 저장 | map |
| 빠른 탐색만 필요 | unordered_map |
| 삽입/삭제 많음 | deque |

정리하면: vector가 기본이고 set/map은 logN, reserve()는 대량 입력 문제 필수, `[]` vs `at()` 차이 숙지, 자동 정렬 특성을 알아야 실수를 막는다.

## 알고리즘 효율성 (챕터 2-5)

| 컨테이너 | 삽입 | 탐색 | 특징 | 사용 상황 |
| --- | --- | --- | --- | --- |
| **vector** | O(1) (뒤) / O(N) (앞) | O(N) | 연속 메모리 | 임의접근 많을 때 |
| **deque** | O(1) (앞/뒤) | O(1)* | 청크 구조 | 앞 삽입 많을 때 |
| **map** | O(logN) | O(logN) | Red-Black Tree | 정렬 필요 시 |
| **unordered_map** | O(1) 평균 | O(1) 평균 | 해시 | 정렬 불필요 + 빠른 탐색 |

표는 이론값이고, 실제 체감 성능은 연속 메모리의 캐시 효율 덕에 vector가 더 빠른 경우가 많다.

**vector vs deque** — `vec.insert(begin(), x)`는 전체 원소가 밀려 O(N), `deq.push_front(x)`는 O(1). 임의접근은 둘 다 O(1)이지만 캐시 효율은 vector 우세. 앞 삽입이 많으면 deque, 그 외엔 vector.

```cpp
vec.insert(vec.begin(), x); // O(N)
deq.push_front(x);          // O(1)
```

vector 앞 삽입은 절대 지양하고, 대량 push_back에는 reserve()가 필수다.

**map vs unordered_map** — map은 내부 정렬 유지로 O(logN), unordered_map은 해시로 평균 O(1). 정렬이 필요 없으면 unordered_map.

```cpp
map<int, int> m;            // O(logN)
unordered_map<int, int> um; // O(1) avg
```

단 unordered_map은 해시 충돌 시 O(N)까지 떨어질 수 있고, 키 범위가 작으면 vector(배열) 치환이 최적이다.

**탐색 성능** — vector+find는 O(N), map.find()는 O(logN), unordered_map.find()는 O(1). 탐색이 빈번한 문제에 vector 선형 탐색은 금물이고, 데이터 10^5 이상이면 해시를 고려한다.

```cpp
find(vec.begin(), vec.end(), x); // O(N)
m.find(x);                       // O(logN)
um.find(x);                      // O(1)
```

**문자열 결합** — `s = s + x`는 매번 새 객체를 만들어 O(N), `s += x`와 `append()`는 내부 버퍼를 제자리 수정해 O(1) amortized. 반복 결합에 `+`를 쓰면 시간초과 위험.

```cpp
s += x;       // 추천
s.append(x);  // 추천
s = s + x;    // 지양
```

**auto vs auto&** — `for (auto x : vec)`는 복사가 일어나고 `for (auto& x : vec)`는 참조라 복사가 없다. 큰 구조체일수록 차이가 커진다. 수정하지 않으면 const auto&, range loop 기본값은 참조로 습관화.

```cpp
for (auto& x : vec) { } // 권장
```

**정렬이 필요 없으면 정렬 비용을 내지 않는다** — map은 삽입마다 정렬을 유지하느라 O(logN)씩 낸다. 단순 카운팅이면 unordered_map, 키 범위가 작으면 배열이 최적이다.

### 코테 핵심 전략

- 앞 삽입 많다 → deque
- 임의접근 많다 → vector
- 빠른 탐색 필요 → unordered_map
- 정렬 필요 → map
- 문자열 반복 결합 → +=
- 반복문은 auto& 기본값

> **오늘 배운 것** — 재귀는 기저 조건 + 문제 축소가 뼈대이고, 시간복잡도는 호출 트리로 판단한다(1개씩 감소 O(N), 2개 분기 O(2^N), 절반 감소 O(logN)). 피보나치처럼 중복 호출이 있으면 메모이제이션으로 O(2^N)을 O(N)으로 줄인다.
